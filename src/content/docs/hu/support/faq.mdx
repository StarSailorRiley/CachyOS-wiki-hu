## Telepítés

### Miért csak a KDE Plasma elérhető a live környezetben?

A KDE Plasma tekinthető a „zászlóshajó” desktop környezetünknek, ezért ez kapja a legtöbb karbantartást. A többi CachyOS ISO-ját félkész állapotban tartottuk karban, ezért a felhasználók számára esetlegesen felmerülő nem kívánt problémák és kellemetlenségek elkerülése érdekében úgy döntöttünk, hogy elavuljuk őket, hogy erőfeszítéseinket a legjobb felhasználói élmény biztosítására összpontosíthassuk.

A CachyOS virtuális gépre telepítését javasoljuk a különböző desktop környezetek és ablakkezelők kipróbálásához, mivel a live ISO-t csak a telepítéshez és a hibás telepítés helyreállításához használjuk a [cachy-chroot](https://github.com/CachyOS/cachy-chroot) segítségével.

### Amikor megnyomom a "Telepítő indítása" gombot, semmi sem történik...?

:::caution[Figyelem]
Győződjön meg róla, hogy aktív/működő internetkapcsolattal rendelkezik, különben semmi sem fog történni a gomb megnyomása után
:::

Bár úgy tűnhet, mintha semmi sem történt volna, a háttérben egy szkript fut, amely a gomb megnyomása után elindul. És mit csinál? Nos, egy előkészítési szkriptet futtat, amelynek célja, hogy elkerülje az olyan lehetséges problémákat, mint például egy elavult keyring.

Adok egy rövid tájékoztatást arról, hogy mit csinál ez a [szkript](https://github.com/CachyOS/CachyOS-Live-ISO/blob/master/archiso/airootfs/usr/local/bin/calamares-online.sh) a háttérben:

<Steps>

1. Eltávolítja a meglévő `/etc/pacman.d/gnupg`-ban található keyring fájlt.
2. Elindítja az `Arch Linux & CachyOS keyring csomagok` telepítését és frissítését.
3. Elindítja és feltölti a pacman keyring-et.
4. Engedélyezi a hálózati idő szinkronizálását a rendszeróra pontosságának biztosítása érdekében a `timedatectl set-ntp true` parancs futtatásával.
5. Meghatározza és ellenőrzi, hogy a rendszer típusa **UEFI vagy BIOS/MBR**.
6. Ha a futó rendszer **UEFI** > a felhasználót felszólítja a rendszerbetöltő kiválasztására, egyébként nem.

</Steps>

**Ezért általában eltart egy ideig a telepítő betöltése.**

### A telepítési folyamatom egy ideje 33%-on elakadt.

Ez azt jelenti, hogy az internetkapcsolatod vagy nagyon lassú, vagy instabil, ami miatt a pacmannek nehézségei vannak a csomagok letöltésével.

## Szoftverkezelés

### "unable to lock database" hiba
```sh
sudo rm /var/lib/pacman/db.lck
```
:::tip[Tipp]
Ugyanezt az eredményt érheted el a `CachyOS Hello` **Alkalmazások/Javítások** lapján található **"Remove data lock"** függvény használatával.
:::

### File is corrupted (invalid or corrupted package (PGP signature))

```text
# Példa:
:: File /var/cache/pacman/pkg/python-charset-normalizer-3.4.0-1-any.pkg.tar.zst
is corrupted (invalid or corrupted package (PGP signature)).
```

```sh title='Futtassa a következő parancsokat'
sudo rm -rf /etc/pacman.d/gnupg/
sudo pacman-key --init
sudo pacman-key --populate

sudo pacman-key --recv-keys F3B607488DB35A47 --keyserver keyserver.ubuntu.com
sudo pacman-key --lsign-key F3B607488DB35A47

sudo rm -R /var/lib/pacman/sync
```

```sh title='A csomagadatbázis frissítéséhez és a teljes frissítés végrehajtásához futtassa a következő parancsot:'
sudo pacman -Syu
# Ezután próbálja meg újra telepíteni a kívánt csomagot.
```

### Mit jelent a csomagnév végén található -bin? Például librewolf-bin

Ez azt jelenti, hogy egy előre elkészített csomagot töltesz le/telepítesz, ezért nem kell kompilálnod vagy felépítened.
A tárolóinkban néhány bin csomagot tárolunk, amelyek alapvetően tükrözések, amelyeket letölthetsz az AUR-ból.

### error: could not remove /var/cache/pacman/pkg/download

:::tip[Tipp]
A pacman gyorsítótárát a CachyOS Hello segítségével is kiürítheted az **Alkalmazások/Tweaks** > **Csomag gyorsítótárának törlése** menüpontban.
:::

#### Példa:

<br />
<ImageComponent imgsrc={import('~/assets/images/pacman-cache-error.png')} />

*Ez általában akkor jelenik meg, ha néhány árva csomag maradt a `/var/cache/pacman/pkg` fájlban, amelyeket a pacman nem tud törölni.*

```sh title='Futtassa a következő parancsot a javításhoz'
# Eltávolítja a pkg gyorsítótárában tárolt összes árvát.
sudo rm -r /var/cache/pacman/pkg/*
```

### ERROR: module not found: 'nvidia', 'nvidia_modeset', 'nvidia_uvm', 'nvidia_drm'

```sh title='Példa'
==> ERROR: module not found: 'nvidia'
==> ERROR: module not found: 'nvidia_modeset'
==> ERROR: module not found: 'nvidia_uvm'
==> ERROR: module not found: 'nvidia_drm'
```

**A hiba két oka:**

**1) Mivel a korai modulbetöltés mindig engedélyezve van a chwd parancsban, az mkinitcpio következetesen NVIDIA modulok jelenlétét várja, ezért ez a hiba akkor jelentkezik, ha ezek a modulok hiányoznak.**

**2) Lehetséges, hogy hiányoznak az NVIDIA modulok a rendszeredre telepített többi kernelből.**

```sh title='Telepítse a következő csomagot a hiba javításához'
sudo pacman -S nvidia
```

### A GitHub honlapja használhatatlanná és rendkívül lassúvá teszi a böngészőt.

  - **Engedélyezze újra a képernyőképen látható módon**

### A böngészőjét a szervezete kezeli. Aggódnom kell?

- *Nem. Ez azért van, mert mellékelünk egy [szabályzatfájlt](https://github.com/CachyOS/CachyOS-Browser-Settings/blob/master/distribution/policies.json), amelyen letiltunk funkciókat és módosításokat adunk hozzá a böngészőhöz. Példa: `további keresőmotorok`.*

### RFP (Resist Fingerprint Protection)

- A Cachy Browser alapértelmezés szerint engedélyezi a `privacy.resistFingerprinting` funkciót. Bár javítja az adatvédelmet, bizonyos problémákat okozhat azoknál a felhasználóknál, akik nincsenek tisztában ezzel, például a következőket:
  - Műhibák a renderelésekor
  - A sötét mód nem alkalmazható
  - Bizonyos weboldalakon nem lehet bejelentkezni (Twitch)
  - Néhány billentyűkombináció nem működik

- Annak ellenőrzéséhez, hogy ez a funkció okozza-e a jelenlegi problémát, tekintse meg a következő [Mozilla cikket](https://support.mozilla.org/hu/kb/resist-fingerprinting), és bontsa ki a **Hogyan ronthatja a weboldalakat a Resist Fingerprinting?** részt.

*Az RFP letiltásához menjen az `about:config` oldalra, keresd meg a **privacy.resistFingerprinting** fájlt, és állítsd `false`-ra*.
