Kernel telepítése egy repository-ból
---------------------------------------

**A CachyOS Kernel Manager egyszerűvé teszi a kernelek telepítését és kezelését bármely Arch Linux adattárból.**

Kernel telepítéséhez indítsa el a `CachyOS Kernel Manager` alkalmazást, és válassza ki a kívánt kernelt a `[]` jelölőnégyzet bejelölésével az összes elérhető opció listájából, majd kattintson az `Execute` gombra a kernel telepítésének megkezdéséhez.

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km1.png')} />

:::note
Az `Execute` gomb nem érhető el, ha egy már telepített kernelt választ.
:::

Egyéni CachyOS kernel konfigurálása és építése
---------------------------------

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km2.png')} />

**The CachyOS Kernel Managerrel egyszerűen konfigurálható és építhető egyéni CachyOS kernel.**

:::note
A CachyOS Kernel Manager kifejezetten a **CachyOS variánsokhoz** készült egyéni kernelek építésére készült, és nem támogatja a szabványos Arch Linux kernel vagy bármely más variáns építését vagy konfigurálását.
:::

*A kezdéshez nyissa meg a Kernel Manager-t, és kattintson a `Configure` gombra a különböző beállítások, például a kívánt ütemező, az órajel-sebesség és egyebek módosításához. Miután elvégezte a kívánt módosításokat, kattintson a `Build kernel` gombra az egyéni CachyOS kernel építésének megkezdéséhez.*

**Elérhető konfigurációs lehetőségek:**

* *`Custom package name`: **Ezzel az opcióval a kernel nevét bármilyen névre adhatod, például: `linux-custom-cachy`***
* *Scheduler (BORE, RC, RT, RT+BORE, EEVDF és BMQ): Ütemező*
* *Enable CachyOS config: Konfig engedélyezése*
* *Tweak Configuration via nconfig, menuconfig, xconfig, or gconfig: Konfig finomhangolása*
* *Enable/Disable NUMA: NUMA ki/bekapcsolása*
* *Enable/Disable Modprobed-db: Modprobed-db ki/bekapcsolása*
* *KBUILD CFLAGS (-O3 vagy -O2)*
* *Performance governor as default: Teljesítményszabályozó alapértelmezettként*
* *Enable BBR3: BBR3 bekapcsolása*
* *Tick rate kiválasztás (100Hz, 250Hz, 300Hz, 500Hz, 600Hz, 750Hz, 1000Hz)*
* *Tickless mód (idle, periodic, full)*
* *Preemption (Full, Voluntary vagy Server): Preempció*
* *Transparent Hugepages (Always vagy Madvise)*
* *Enable/Disable DAMON: DAMON ki/bekapcsolása*
* *Enable/Disable Automatic CPU arch detection: Automatikus CPU arch észlelés ki/bekapcsolása*
* *Apply kernel optimization for specific CPU architectures: Kernel optimalizáció adott CPU architectúrákhoz*
* *Enable LTO (Full, Thin, No): LTO bekapcsolása*
* *Build ZFS Module: ZFS modul építése*
* *Build NVIDIA Closed Module: NVIDIA zárt modul építése*
* *Build NVIDIA Open Module: NVIDIA nyílt modul építése*
* *Include vmlinux with debug information/symbols: vmlinux debug beillesztése*
* *Kernel Manager konfig előbeállítás betöltése/mentése: `(Csak magából a Managerből származó beállítások)`*
* *Kernel Patch Management (Remote és Local támogatás)*

**A kernel sikeres felépítése után a rendszer kéri a sudo jelszavát a kernel telepítéséhez.**

## Sched-ext framework management

**A Kernel Manager grafikus felhasználói felületet (GUI) biztosít a sched-ext ütemezők kezeléséhez és vezérléséhez. A grafikus felület a főablakban található „sched-ext ütemező konfigurációja” gombra kattintva érhető el.**

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km3.png')} />

Ez a grafikus felhasználói felület a következőket teszi lehetővé:

- **Váltás a különböző sched-ext (scx) ütemezők között.**
- **Az ütemező szolgáltatás engedélyezése vagy letiltása.**
- **Az aktuálisan futó ütemező ellenőrzése.**
- **Ütemező jelzők és profilok beállítása. `Jelenleg csak a bpfland és a lavd profilokat támogatja.`**

Ennek eléréséhez a Kernel Manager az `scx_loader` fájlt használja, amelynek konfigurációja a következő helyen van tárolva:

`/etc/scx_loader.toml`.  Az `scx_loader` konfigurációs fájllal kapcsolatos további információkért tekintse meg [ezt a dokumentációt](https://github.com/sched-ext/scx/blob/main/rust/scx_loader/configuration.md).

- **Hogyan működik az `scx_loader`?**
    - Miután kiválasztotta az ütemezőt és a profilt, az scx_loader elindítja az ütemezőt a kiválasztott profillal, és elmenti ezt a konfigurációt az `/etc/scx_loader.toml` fájlba, hogy az újraindítások után is megőrizze azt. Példa arra, hogy hogyan fog kinézni a fájl az `scx_bpfland` beállítással és a `Gaming` profillal:
        ```toml
        default_sched = "scx_bpfland"
        default_mode = "Gaming"

        [scheds.scx_bpfland]
        auto_mode = []
        gaming_mode = ["-m", "performance"]
        lowlatency_mode = ["-k", "-s", "5000", "-l", "5000"]
        powersave_mode = ["-m", "powersave"]
        ```

### Ütemezőprofilok

- **Mire valók a "profilok"?**
  - Ezek az ütemező előre beállított értékei, amelyek a bevált kombinációk alapján módosítják a jelzőket, hogy növeljék a hatékonyságot bizonyos felhasználási esetekben, például a "Játék" esetében.

**A részletesebb áttekintésért tekintse meg a táblázatot.**

#### Bpfland

|   Profil neve  	|  Parancssori jelzők  	|                                                         Leírás                                                         	|
|:---------------:	|:--------------------:	|:---------------------------------------------------------------------------------------------------------------------------:	|
| **Low Latency** 	| `-k -s 5000 -l 5000` 	| Célja a késleltetés csökkentése az átviteli sebesség rovására. Valós idejű alkalmazásokhoz, például hangfeldolgozáshoz és multimédiához alkalmas. 	|
| **Gaming**      	| `-m performance`  	| Játékokban a nagy teljesítmény érdekében optimalizál. Az Intel CPU-kon a P-magokat részesíti előnyben az E-magokkal szemben, a Ryzen X3D CPU-kon pedig a CCD-ket.        	|
| **Power Save**  	| `-m powersave`       	| Az energiahatékonyságot helyezi előtérbe. A kisebb teljesítményű magokat részesíti előnyben (pl. az Intel E-magjait).                                          	|
| **Server**        | `-c 0`                | Letiltja az interaktív feladatosztályozást a Bpflandban, így hatékonyabbá teszi a szerverek működését, ami várhatóan körülbelül 2-3%-os szerverterhelés-növekedést eredményez.

#### LAVD

|       Profil neve       	| Parancssori jelzők 	|                                                             Leírás                                                            	|
|:------------------------:	|:------------------:	|:----------------------------------------------------------------------------------------------------------------------------------:	|
| **Gaming & Low Latency** 	|   `--performance`  	| Maximalizálja a teljesítményt az összes elérhető mag kihasználásával, a fizikai magokat előnyben részesíti.                                                  	|
|      **Power save**      	|    `--powersave`   	| Minimalizálja az energiafogyasztást, miközben fenntartja az elfogadható teljesítményt. A hatékony magokat és szálakat részesíti előnyben a fizikai magokkal szemben. 	|
